# 선회 평지 패드 + 하이트맵 PNG y-플립 발견 (2026-08-11)

## 요약

횡단 산포(회당 ~50% 동전 던지기)의 지형 수준 해법으로 **선회 평지 패드**를 구현했다.
1차 하네스에서 큰 단차 쌍만 이유 없이 정체하는 현상을 추적하다가, 프로젝트 전체를
관통하는 근본 버그를 발견했다: **시뮬레이터의 충돌 지형이 3주 내내 남북으로 뒤집혀
있었다.** 수정 후 하네스 **48/48 전 통과**(8개 횡단 × P0·P9 × 3회, 균일 ~10초, 정체 0).

## 선회 평지 패드 (gen_heightmap `--turn-pads`, 기본 켬)

- 부스트로피돈 파리티 그대로: 쌍 (k,k+1) — 짝수 k는 북단, 홀수 k는 남단. 8개.
- 패드 높이 = 두 통로 평균 → 진입(통로 k 이탈)·진출(통로 k+1 재진입)이 각각 **반 단차의
  직선 y-램프**(2.0 m, smoothstep 피크 ≤19%)가 되고, U-호 전체는 평지에서 돈다.
  직선 등판은 종전 하네스에서 이미 12/12였다 — 경사 위 선회만 제거하면 된다는 설계.
- 수목 구간(|y|≤30)은 바이트 단위 불변(같은 seed·같은 단차표). 오프라인 검증:
  호 풋프린트 평탄 1.7–4.0 cm, 임무 횡단선 횡경사 8–14% → **0.0–0.1%**.
- 패드 x 마진 1.6 m(1.75 초과 시 이웃 패드와 겹침), 가장자리 블렌드 0.6 m,
  울타리 밖 |y| 40→43에서 램프로 복귀.

## 근본 버그: 하이트맵 PNG 행 방향

- **Gazebo는 하이트맵 이미지의 행 0(위)을 +y(북)에 매핑한다.** write_gray_png는 행 0 =
  y=−60(남)으로 써 왔다 → 시뮬의 충돌·시각 지형은 우리 좌표계의 **상하 반전**이었다.
- 종전 지형은 남북 대칭(테라스는 x-프로파일, 선회 램프 블렌드도 대칭)이라 3주간 무증상.
  패드가 최초의 남북 비대칭 지형이라 즉시 발각: 로봇이 "평지"에서 벽에 박히고(뒤집힌
  이웃 패드 사이 둑), 지형을 관통해 낙하(z=−30)·사출(z=+343)됐다.
- 진단 결정타: 정착 z-프로브 — 텔레포트 후 정지 자세의 z·roll·pitch 를 npy 기대값과
  비교. 뒤집힌 npy 값과 4/4 일치. 수정(`write_gray_png(path, png[::-1])`) 후 10/10
  지점 Δ≤1 cm · 기울기 0.
- 함의: 과거의 실측 상수들(황금 대역, 벽 테이블, 남북 비대칭 출구 깊이)은 "그 당시
  시뮬"에 대한 실측이므로 당시 결과 해석은 유효하나, 지형 좌표 기반 추론(어느 램프가
  얕다 등)은 재검이 필요하다. 남측 겉보기 벽이 얕았던 것은 구조물(방풍림·진입로) 요인.

## 연쇄 수정

1. **맵 번들(37)**: 패드가 통로 쌍을 물리로 이어 자유공간이 사다리 → **뱀형**.
   스켈레톤 엣지 하나가 U-호 너머 두 통로에 걸쳐 끝점 변위 기준(along_row)이 실패
   → `column_runs`(수목 구간 |y|≤30 안의 연속 런 단위 분류 + 통로 병합)로 교체.
   9개 중심선 RMSE 58 mm, 되읽기 5/5.
2. **벽 테이블(47)**: 플립 수정 후 재교정. 대부분 울타리선 ±37–39, 산포 ≤0.13.
   **"5:south" 제외** — (5,6)S 50 cm 단차 쌍의 진입램프 면이 겉보기 벽으로 잡히는데
   관측 위치 의존(산포 1.84 m)이라 '통로×단별 상수' 전제가 깨진다. map_localizer는
   키 부재 시 해당 단 앵커를 건너뛴다.
3. **하네스(46)**: P9 목표 y 하드코딩 제거(Y_TGT), `--mission-pairs` 모드 추가
   (미션 파리티대로 8개 횡단 순회).
