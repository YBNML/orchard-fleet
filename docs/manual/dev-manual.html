Overview

무엇을 만드는가

이 프로젝트는 예전 스타트업에서 운용하던 장비 구성(Scout Mini + Livox MID-70)을 시뮬레이션으로 재현해, 실제로 수집했던 데이터와 비교 가능한 파이프라인을 다시 세우는 작업입니다. 실제 과수원을 컴퓨터로 주행할 수는 없으므로, 노지 사과 과수원을 Gazebo에 절차적으로 생성하고 그 안에서 로봇이 자율주행하며 데이터를 수집합니다.

Environment

먼저 넘은 두 블로커

1. NVIDIA 드라이버 (Secure Boot)

DKMS가 빌드한 nvidia.ko가 머신 소유자 키로 서명됐으나 그 키가 MOK에 등록되지 않아 커널 lockdown이 로드를 거부. 모니터가 NVIDIA 카드에 꽂혀 있어 화면은 가속 없는 프레임버퍼로 나오고 GPU는 놀고 있었습니다. MOK 등록 + prime-select nvidia로 복구.

# MOK 등록 (재부팅 시 파란 화면에서 Enroll)
sudo mokutil --import /var/lib/shim-signed/mok/MOK.der
sudo prime-select nvidia   # ★ on-demand면 gz sim이 계속 iGPU를 씀
sudo reboot
복구 확인

nvidia-smi → GTX 1660 SUPER 580.173.02 · card2 → nvidia · OpenGL renderer NVIDIA GeForce GTX 1660 SUPER (llvmpipe/Intel 아님)

2. packages.ros.org HTTPS 인증서 불일치

OSU 미러로 CNAME되며 *.osuosl.org 인증서를 제시해 HTTPS가 실패. 그러나 공식 ros2-apt-source .deb가 원래 http://로 설정하고 무결성은 GPG 서명으로 보장하므로 우회가 필요 없습니다. https://packages.ros.org 소스 줄을 손으로 쓰지 말 것.

단계 00

ROS 2 Jazzy + Gazebo Harmonic 설치

완료 · 검증

네이티브 설치. Docker 없음, Gazebo Classic 없음. Gazebo는 Jazzy부터 ros-jazzy-*-vendor 패키지로 오므로 packages.osrfoundation.org를 추가하지 않습니다(두 벌 설치 충돌).

단계 01

라벨 인스턴스 분리 실측 + 사과나무 생성기

완료 · 검증

두 리서치 브리프가 "과실을 어떤 SDF 구조로 배치해야 인스턴스 분리가 되는가"에서 정면 충돌했습니다. 월드 생성기 아키텍처 전체가 여기 달려 있어 5개 구성을 한 월드에 넣고 실측으로 결정했습니다.

구성SDF 구조기대실측판정
A한 모델 / 한 링크 / visual 3개31뭉개짐
B한 모델 / 링크 3개31뭉개짐
C최상위 <model> 3개33분리
D최상위 <include> 3개33분리
E부모 모델 안 중첩 <include>31뭉개짐
함정 회피

인스턴스 분리는 최상위 non-nested 모델 단위로만 일어납니다. 브리프 2의 "per-visual Label로 인스턴스가 자동 부여된다"는 반증됐습니다. 그대로 갔다면 마스크는 그럴듯하지만 인스턴스가 나무당 1개 — 착과 카운팅 정답이 통째로 무의미해질 뻔했습니다. 부수적으로 panoptic 채널 인코딩도 브리프와 반대(ch2=라벨, ch0·ch1=인스턴스)임을 확인했습니다.

Blender 사과나무 생성기

다운로드 가능한 과수 에셋이 없어(Fuel 13개 검색어 조회 결과 0개) 절차적으로 생성합니다. 세장방추형은 의도적으로 인위적인 수형이라 직접 스크립팅이 자연스러운 분기 생성기보다 쉽습니다.

blender --background --python scripts/gen_tree.py -- \
        --seed 42 --severity 7 --out sim/models
# → severity 7 → DEFECT (임계 6) · 잎 병징 42% · 과실 60(병징 11)
# → 삼각형 body 1,692 / full 6,492 / 공유 과실 80

메시는 glTF(.glb)로 내보냅니다 — Ubuntu 24.04 Blender 4.0.2에 COLLADA 익스포터가 없고, gz-common5-graphics가 libassimp.so.5에 링크돼 glTF를 읽습니다. <submesh>로 파일 하나에서 부위별 라벨을 붙입니다.

단계 02

과수원 월드 생성기 + 지형

완료 · 검증

지형 하이트맵(513×513 8-bit)과 나무·지주·2존 지면을 절차적으로 배치합니다. 실측(§01)에 따라 2계층 구조를 강제합니다 — 배경목은 과실 구워넣은 통짜 모델 <include>, 계측 블록은 나무 몸체 + 과실마다 최상위 <include>로 인스턴스를 확보합니다.

단계 03

Scout Mini + MID-70 로봇 모델

완료 · 검증

제원은 westonrobot/scout_ros2 스펙과 일치시키되, 관성은 재계산했습니다 — 기존 파일의 휠 관성이 Husky 유산으로 40–285배 과대했고 이는 스키드스티어 요 응답을 지배해 시뮬 튜닝 게인을 실기에서 무용하게 만듭니다. 구동은 gz-sim DiffDrive(실제 scout_base가 독립 노드라 gz_ros2_control은 쓰지 않음).

MID-70 마운트 (D12 — 실제 구성 재현)

로봇과 같은 방향(틸트 없음), 로봇보다 40 cm 높게, 앞면 정렬 → base_link 기준 (0.275, 0, 0.645). 틸트가 없어 지면 사각이 전방 0.91 m 생기지만, 대신 수관 상단(수고 3.2 m)이 3.5 m 앞에서 시야에 들어옵니다.

라벨 체계 & severity 매핑

정답 세그멘테이션 라벨 ID(0–255)와 병해 severity→외형 매핑입니다. 기존 파이프라인(Fast R-CNN 부위검출 → ResNet18 분류)이 부위 단위이므로 라벨도 부위 단위로 설계했습니다.

ID클래스ID클래스
10ground30leaf_healthy
12trellis_post31leaf_diseased
20trunk40fruit_healthy
21branch41fruit_diseased

D13 병해 판정: 생성기가 나무마다 severity 0–10을 정답으로 함께 출력하고, 이진 라벨은 severity ≥ 6로 파생합니다. 원본 severity를 보존하므로 임계값을 바꿔도 재라벨링이 불필요합니다.

severity 0 ~ 5   →  정상   (NORMAL)
severity 6 ~ 10  →  병충해 (DEFECT)
