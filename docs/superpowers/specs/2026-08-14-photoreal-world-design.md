# 실사 정사영상 기반 과수원 월드 + 관제 실사 지도 — 설계 (스펙 ④)

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-08-14 |
| 전제 | 스펙 ③ 병합 완료(2대 동시 운용·AlleyLock·BT) |
| 목표 | 실제 항공 정사영상을 기반으로 시뮬 월드를 재구축하고, 관제 지도를 그 실사 이미지 위에 올려 "실제 농장을 관제하는" 실체감을 만든다 |

## 0. 원칙

1. **이미지가 기준이다** — 월드 기하(열 방향·간격·범위)는 이미지에서 나오고, 시뮬·측위·관제가 그 기하를 공유한다. 정합의 단일 출처는 농장 기하 매니페스트(`farm.json`) 하나다.
2. **라이선스 위생** — 공개 저장소에 들어가는 모든 외부 이미지는 재배포 가능 라이선스 + 출처 표기를 `assets/imagery/LICENSE-DATA.md` 에 기록한다. 근거가 불명확하면 쓰지 않는다.
3. **기존 파이프라인 재사용** — gen_world/gen_heightmap/번들 빌드(37)/벽 캘리브레이션(47)의 확장이지 재작성이 아니다. 계단식 월드와 그 캘리브레이션 자산은 연구용으로 보존한다(파일 교체가 아니라 병존).
4. **센서 기하는 여기서 한 번에** — 상부 구조(아치+D455 마운트) 변경이 측위 캘리브레이션을 바꾸므로, 기하는 ④에서 확정·반영하고 ⑤는 기능만 얹는다.

## 2. 농장 기하 매니페스트 (`maps/orchard_real/farm.json`)

이미지에서 반자동 추출(구현 도구: 대화형 스크립트 — 열 축 후보를 자동 검출(식생지수·주기성)하고 사람이 확정)한 **정합의 단일 출처**:

```json
{
  "image": "orchard_ortho.jpg",
  "px_per_m": 4.0,                  // GSD 25cm 기준
  "origin_px": [x0, y0],            // 월드 (0,0) 의 픽셀 위치
  "rotation_deg": r,                // 월드 x축 대비 이미지 열 방향
  "rows": N, "row_spacing_m": s,    // 이미지에서 추출
  "row_length_m": L, "tree_spacing_m": t,
  "row_origins": [[x,y], ...],      // 각 열 시작점(월드 좌표)
  "headland_m": h, "bounds_m": [[minx,miny],[maxx,maxy]]
}
```

- 월드↔픽셀 아핀 변환은 `origin_px`+`rotation_deg`+`px_per_m` 세 값으로 정의 — 시뮬(나무 배치), 대시보드(지도 정합), 검증(정합 오차 측정)이 전부 이 파일을 읽는다.
- 통로 수·간격의 하드코딩(스펙 ③ 이월: BT `N_ALLEYS=9`, 대시보드 지도 기하 상수, 미션 엔진 격자 상수)은 이 매니페스트 소비로 대체한다.

## 3. 월드 재구축

- **지형**: 평탄 + 완경사 ≤3°(이미지의 자연스러운 색·음영과 어울리는 범위, gen_heightmap `--flat-gentle` 신설). 선회 패드·계단·둑 없음. 지면 텍스처는 정사영상 크롭을 그대로 지면에 입힌다(시뮬 안에서도 실사 지면 — 카메라 뷰 실사감).
- **나무 배치**: `farm.json` 의 열 기하에 격자 스냅(개별 나무 픽셀 추출은 하지 않는다 — 측위가 격자 위상 기반). 수종 모델은 기존 사과나무 자산 재사용.
- **gen_world 확장**: `--farm maps/orchard_real/farm.json` 입력 모드 신설(기존 `--rows/--trees-per-row` 모드는 계단식 월드용으로 유지). 로봇 스폰은 scout01=통로 0 남단, scout02=분담 B 시작 통로 남단(매니페스트 분할값에 따름).
- **월드 병존**: 신규 `sim/worlds/orchard_real.sdf` + `maps/orchard_real/` 번들. 기존 `orchard_nav.sdf`·`maps/orchard_v1/` 은 그대로 둔다. 런치 `world:=real|terraced` 인자로 선택, 기본값은 게이트 통과 후 `real`.
- **상부 센서 기하(확정 하이브리드 — 브레인스토밍 목업 기준)**: model.sdf 에
  - 롤바 아치(차폭 스팬, 시각 지오메트리) + **MID-360 아치 상단 중앙, 지상 0.80m**
  - **D455 노즈 브래킷, 지상 0.55m, 하향 12°** — ④에서는 시각 지오메트리+프레임(TF)만, 센서 플러그인 활성화는 ⑤
  - 분석 카메라 L/R 아치 다리 측면 재배치, 앰버 경광등(시각), 아치 뒤 적재 데크(시각)
  - 라이다 자기반사 필터를 아치 다리 음영 2줄 기준으로 재도출

## 4. 측위 재캘리브레이션

- 새 월드에서 번들 빌드(37 — 평탄이라 serpentine 분류 불필요, 통로가 사다리형으로 회귀)·벽 테이블(47 — 새 경계 구조물 기준) 재실행. 라이다 높이 0.80m 반영(벽 콘 z 대역 재확인).
- 평탄 지형의 귀결을 명시적으로 적용: 선회 패드 파리티 제약 **해제**(BT 프리셋 `parity_safe` 검증은 계단식 월드에서만 활성 — 월드 종류를 서버가 알아야 하므로 farm.json 에 `terrain: "flat"` 필드, 프리셋 검증이 이를 읽음), 횡단 등판 정책(lost 대비 런타임 파라미터) 불필요.
- 기존 미해결 항목(선회 구역 보정 자기잠금)은 평탄 월드에서 발생 조건(등판 슬립)이 사라지므로 이 월드에서는 비활성 리스크 — 수리 자체는 계단식 트랙의 몫으로 남는다.

## 5. 관제 실사 지도

- 지도 캔버스 바탕에 정사영상 렌더(월드↔픽셀 아핀 — farm.json 소비). 기존 오버레이(로봇·궤적·통로 점유 밴드·BT·개입)는 그 위에 유지.
- **벡터/실사 토글**(기본 실사) + 이미지 로드 실패 시 벡터 폴백(조용한 빈 지도 금지).
- 이미지 서빙: 서버 정적 경로로 `orchard_ortho.jpg` 제공(웹용 재압축 ≤2MB 목표).
- 통로 선택기·클릭 판정은 기존 기하 코드가 farm.json 기반으로 일반화된 것을 그대로 사용.

## 6. 오류 처리

- farm.json 없음/불일치(이미지 해시 불일치): gen_world·서버 기동 시 명시적 실패(무음 기본값 금지).
- 정사영상 로드 실패(대시보드): 벡터 지도 폴백 + 콘솔 경고 1회.
- 열 추출 도구는 확정 전 시각 확인 출력(이미지 위에 열 축 오버레이 PNG)을 남긴다 — 사람 승인 없이 farm.json 을 쓰지 않는다.

## 8. 사용자 확정 사항 (브레인스토밍 기록)

- 실사 기반 재구축(월드를 이미지에 맞춤) / 지형 평탄·완경사 / 상부 = 롤바 아치 + 노즈 D455 하이브리드(수치는 §3) / D455 기능·헤드랜드 우회는 스펙 ⑤.
