## 0. 왜 스펙을 고치는가

v1.1은 "관제가 로봇을 감독한다"는 그림 위에 세워졌다. 리서치는 이 그림의 두 전제를 흔들었다.

**전제 1 — "관제 화면에서 비상정지를 풀 수 있다"**: ISO 13849-1 §5.2.2는 리셋 액추에이터가 위험구역 밖의 **시야 확보된 위치**에 있을 것을 요구한다. 사무실에서 지도만 보고 누르는 해제 버튼은 이 요건을 만족하지 않는다. 다만 같은 조항이 시야가 불완전할 때 **특별 리셋 절차**를 허용하므로, 금지가 아니라 **절차 설계 문제**다.

**전제 2 — "여러 대를 나란히 감시한다"**: 상시 감시형 상호작용의 실측 상한은 2~5대다(Coventry 실험 최적 5대, 평균 반응 13초). 흔히 인용되는 1:43(Waymo)은 검증 결과 **동시근무 인원 ÷ 보유 대수**를 나눈 언론 파생치였고, 원문은 운영자:차량 비율을 영업비밀로 공개 거부했다. GUSS의 1:8도 감시자가 **픽업트럭에서 기체를 눈으로 보는** 현장 가시선 감독이다. 다대 감시가 성립하려면 화면이 감시형이 아니라 **호출 큐**여야 한다.

## 2. 비상정지 해제 — 특별 리셋 절차 (D10)

### 2.1 규격 요구와 대응

| 요구 | 출처 | 우리 대응 |
|---|---|---|
| 리셋은 고의적 수동 동작 | ISO 13850 | 2단계 모두 명시적 조작 |
| 리셋이 곧 재시동이 되어선 안 됨 | ISO 13850 | 래치 해제 ≠ 임무 재개 (D11) |
| 리셋 위치는 위험구역 밖 + 시야 확보 | ISO 13849-1 §5.2.2 | 1단계를 **현장에서** 수행 |
| 시야 불완전 시 특별 절차 | ISO 13849-1 §5.2.2 | 아래 2단계 절차가 그것 |
| 자동 재시동 금지 | ISO 3691-4 / B56.5 | 재개는 별도 `mission_resume` |

### 2.2 상태 기계

```
     [정상] ──estop──▶ [정지·래치]
                          │
              관제 admin  │ clear_estop_request
                          ▼
                     [해제 대기]  ── 창 만료(기본 10분) ──▶ [정지·래치]
                          │
                현장에서  │ local_reset  (로봇 물리 버튼 / 로컬 확인)
                          ▼
                       [정상]        ※ 임무는 PAUSED 유지 — 재개는 별도 지시
```

- **순서 무관**: 현장에서 먼저 눌러도 된다. 이 경우 `local_reset`이 창을 열고 관제 승인을 기다린다.
- **창 만료**: 두 단계 사이 간격이 `reset_window_s`(기본 600초)를 넘으면 무효화하고 래치로 되돌린다.
- **감사**: 두 단계 각각, 그리고 최종 해제를 별도 기록한다. `estop` 시각과 `local_reset` 시각의 차이가 **현장 출동 왕복시간**이며 D14 지표로 집계한다.

### 2.3 계약 변경

| 항목 | v1.1 | v1.2 |
|---|---|---|
| `cmd: clear_estop` | 즉시 해제 | **제거** |
| `cmd: clear_estop_request` | — | 신설. admin. 해제 대기 진입 |
| `cmd: clear_estop_cancel` | — | 신설. admin. 대기 취소 |
| `evt: local_reset` | — | 신설. 로봇→서버. 현장 확인 발생 |
| `tel/state.estop_stage` | — | 신설. `latched` / `awaiting_local` / `awaiting_remote` / `clear` |

로봇은 `clear_estop_request`만으로 절대 래치를 풀지 않는다 — 서버가 손상돼도 현장 확인 없이는 로봇이 움직이지 않는다(v1.1 원칙 4의 실현).

## 3. 정지 사유 코드 (D12)

ISO 18497-3의 위험 카탈로그를 코드표로 채택한다. 백지에서 만들지 않는다.

| 코드 | 사유 | 분류 |
|---|---|---|
| `OBSTACLE_FRONT` | 전방 정지 영역 내 장애물 | 인지 |
| `NEGATIVE_OBSTACLE` | 전방 지면 소실 (법면·구덩이) | 인지 |
| `SLOPE_SCAN_DEVIATION` | 경사로 스캔 평면 이탈 | 인지 |
| `SENSOR_CONTAMINATION` | 센서 오염·가림 | 센서 |
| `SENSOR_TIMEOUT` | 센서 무응답 | 센서 |
| `LOCALIZATION_LOST` | 정합 실패 지속 (S10) | 측위 |
| `LOCALIZATION_UNCERTAIN` | 공분산 상한 초과 | 측위 |
| `TILT_LIMIT` | 기울기 한계 초과 | 자세 |
| `TRACTION_LOSS` | 슬립·구동 상실 (진흙) | 구동 |
| `GEOFENCE` | 주행가능 영역 이탈 시도 (S9) | 경계 |
| `BATTERY_LOW` | 저배터리 정지 | 전원 |
| `LINK_LOST_POLICY` | 링크 단절 정책에 의한 정지 | 통신 |
| `ESTOP_REMOTE` / `ESTOP_LOCAL` | 비상정지 (관제 / 현장) | 지시 |
| `MISSION_DONE` / `OPERATOR_PAUSE` | 정상 종료 / 지시 정지 | 정상 |

각 코드는 `사유 · 분류 · 개입필요여부 · 현장출동필요여부`를 갖는다. 개입 큐(D13)와 지표(D14)가 이 분류를 그대로 쓴다.

---

## 4. 개입 큐 (D13)

로봇이 스스로 처리 못 하는 상황에서 **요청을 올린다**. 관제는 이를 티켓처럼 처리한다.

```
로봇: evt/assistance  {code, severity, needs_site_visit, context}
        ↓
서버:  interventions 테이블 (open → acked → resolved)
        ↓
대시보드: 큐 화면 (미처리 건수 배지, 오래된 순, 처리시간 측정)
```

- 상태: `OPEN` → `ACKED`(관제가 잡음) → `RESOLVED`(해소) / `ESCALATED`(현장 출동 필요)
- 처리시간: `OPEN→ACKED`(응답), `OPEN→RESOLVED`(해결) 두 값을 모두 기록
- 화면 우선순위: **큐가 비어 있으면 지도가 주인공, 큐에 건이 있으면 큐가 주인공**

## 5. 지표 (D14)

기존 `가동률` 중심을 폐기하고 다음 다섯을 헤드라인으로 둔다.

| 지표 | 정의 | 왜 |
|---|---|---|
| 개입/작업면적 | 개입 건수 ÷ 처리 면적 | 거리 기준은 통로 길이에 좌우돼 왜곡 |
| MTBI | 능동 운용시간 ÷ 개입 건수 | 대기 시간을 빼지 않으면 부풀려짐 |
| 처리시간 p50/p95 | OPEN→RESOLVED | 평균은 꼬리를 숨긴다 |
| 현장 출동 왕복 | `needs_site_visit` 건수 × (estop→local_reset) | 규격상 사람이 반드시 이동해야 하는 비용 |
| 실가동일수 | 연간 실제 작업일 | 국내 농기계 임대 실적 대당 연 11.4일 — 경제성의 실제 병목 |

**무엇을 개입으로 셀지 먼저 못 박는다** (캘리포니아 DMV 사례: 정의가 없으면 지표가 곧 조작 대상이 된다). 정의: *"로봇이 스스로 계획을 이어가지 못해 사람의 판단·조작·이동을 요구한 사건"*. 정상 종료·지시 정지는 개입이 아니다.

## 6. 상태 모델 확장 (D15)

사망 사고는 자율주행 중이 아니라 **점검·시운전 중** 또는 **정지 직후 자동 기동 중**에 발생한다(Cruise 사례). 따라서 다음을 1급 상태로 감시한다.

| 모드 | 의미 | 관제 표시 |
|---|---|---|
| `mission` / `teleop` / `idle` | 기존 | 기존 |
| `maintenance` | 정비 중 — 사람이 기체에 접근해 있음 | **원격 명령 전면 차단**, 화면 상단 경고 |
| `commissioning` | 시운전 — 제한 속도, 감시 필수 | 속도 상한 표시, 개입 큐 우선순위 상향 |
| `awaiting_reset` | 해제 대기 (§2) | 어느 단계가 남았는지 명시 |

계단식 지형의 1순위 위험은 충돌이 아니라 **전도·전복**이므로(국내 농기계 치사율 6.1%, 자동차의 8.7배), 기울기는 경고(20°)·정지(25°)에 더해 **누적 위험 노출 시간**을 기록한다.

## 부록 — 리서치에서 반박된 주장 (인용 주의)

설계 근거로 쓰면 안 되는 수치들:

- **Waymo 1:43** — 동시근무 인원 ÷ 보유 대수를 나눈 파생치. 원문은 비율을 영업비밀로 비공개. 3교대 반영 시 총원 기준 1:10~15
- **GUSS 1:8~10** — 벤더/자사 인터뷰 인용이며, 감시자가 **기체를 눈으로 보는 위치**에 있는 현장 가시선 감독
- **"국내 자율주행 검정 대상은 트랙터·콤바인·이앙기뿐"** — 사실 아님. SS기·동력운반차 포함 32모델 검정 통과
- **"운전자 감지 의무"** — 제정 고시가 아니라 2026년 추진 계획의 예시 항목
- **Cruise 1:1.5** — 원격 인력이 아니라 전체 운영 인력 기준

확인된 것: Coventry 3~9대(최적 5대, 평균 반응 13초), ISO 3691-4의 원격조종 차량 범위 배제, ISA-18.2 알람률(시간당 6건 미만), 농기계 임대사업소 475개소·9.9만 대·대당 연 11.4일, 2024년 농기계 사고 894건·사망 73명.
