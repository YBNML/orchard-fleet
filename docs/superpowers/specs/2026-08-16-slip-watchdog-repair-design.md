## 0. 원칙

1. **진짜 슬립 검출은 한 치도 물러서지 않는다** — 08-02 사고(헤드랜드 둑에 코 박힘, 구조점 0, 오도 환상 4.3m)와 08-03 기하맹 시나리오의 기존 방어는 회귀 시험으로 고정한다.
2. **증거의 등급을 구분한다** — 줄기 구조 상관(고신뢰)과 생구름 폴백(저신뢰)은 같은 발언권을 갖지 않는다. 저신뢰 증거는 물증 동반 시에만 확정에 쓴다.
3. **보정은 실측만큼만** — 추정을 되돌릴 때는 측정이 설명하지 못한 양만큼만 되돌린다. 맹목 복귀 금지.

## 1. 수리 A — 축퇴 게이트 (오탐 차단)

- `_slip_points` 가 반환값에 **출처 표지**를 더한다: `(points, from_fallback: bool)` — 줄기 구조(≥150점)면 False, 생구름 폴백이면 True.
- `_check_slip` 의 슬립 **확정 시점**(`_slip_count >= 2`)에서, 두 점검 창 중 **하나라도 폴백 증거였으면** 물증을 요구한다:
  - 물증 = 코앞 밀착: `last_cloud` 의 `r < 1.2 m` 비율 ≥ 0.25 (기존 기하맹 탈출구 `:522-527` 와 동일한 검사 — 새 잣대를 발명하지 않는다).
  - 물증 없음 → 확정하지 않고 카운터 유지 채 판단 보류(로그 1줄: "슬립 신호 보류 — 폴백 증거·전방 개활"). 감시는 계속되므로 이후 줄기 구조가 돌아와 재확인되면 정상 확정된다.
- 줄기 구조 두 창으로 확정되는 경우는 **현행과 완전 동일**(계단식 경로 불변).
- 잔여 위험(명시): 열 끝 저신뢰 구간에서 전방 개활인 **진짜** 슬립은 확정이 늦어진다 — 그 구간은 5~7m 로 유계이고, 코앞 밀착·자세 이상·lost 타이머가 후방 방어선이다.

## 2. 수리 B — 실측 되감기 (스냅백 완화)

- 현행: 확정 시 `T_mo = compose(_slip_anchor, inverse(T_ob))` — 추정을 카운트 시작 전 자세로 전량 복귀(실측 1.2~1.3m 되감김, 오탐이면 파괴적).
- 변경: 두 점검 창의 `Σ(odo_d_i − max(travel_i, 0))` 를 **설명 안 된 전진량** 으로 계산해 0 이상으로 클램프하고, 그만큼만 **오도 진행 방향의 역으로** 현재 추정에서 차감한다. 요는 건드리지 않는다(관측된 요 점프는 스냅백의 산물이었다 — §9 원자료).
  - 진짜 슬립(travel≈0): 되감기 ≈ Σodo — 기존 의도와 같은 크기, 이제 실측 근거가 붙는다.
  - 오탐이 A 를 통과한 극단 경우: 피해가 실측 불일치만큼으로 유계.
- 이를 위해 `_check_slip` 은 카운트 창마다 `(odo_d, travel)` 쌍을 보관한다(카운터 리셋 시 함께 소거).
- `slip_active` 동결·`assistance`(TRACTION_LOSS) 개입 요청·`resolved` 해제 의미는 전부 불변. 개입 payload 에 진단 필드 추가: `{"odo_m":…, "scan_m":…, "fallback":bool, "rewind_m":…}` — 차후 법의학용(서버 스키마 무변 — data 안).

## 3. 오류 처리·경계

- 폴백 점군이 `None`(판단 불가)인 기존 경로 무변. 회전 중 판단 유보(6°) 무변. 기하맹 탈출구(횡단 방위+개활) 무변 — A 는 그 **앞단**에 놓인 독립 게이트다.
- 파라미터 신설 없음(YAGNI) — 물증 잣대는 기존 상수 재사용. 폴백 표지는 내부 상태로만.
